# 20 - Data Privacy and Ethics

## Purpose

This project may eventually process real company documents. Even public documents must be handled carefully and transparently.

## Data Types

### Synthetic Data

Synthetic data is safe for MVP and should be clearly labeled.

### Public Company Documents

Public annual reports and investor presentations can generally be used for educational and portfolio analysis, but source attribution should be clear.

### Private Company Documents

Private documents should not be used unless permission is granted.

## Rules

1. Do not upload confidential documents to public repositories.
2. Do not expose private financial data.
3. Do not pretend synthetic data is real.
4. Do not generate investment advice.
5. Do not make unsupported claims about company health.
6. Always include limitations when using extracted or synthetic data.

## AI Use Policy

AI may be used to:

- assist with document conversion
- suggest metric mappings
- generate draft summaries
- review documentation
- help write code

AI must not be used to:

- fabricate financial metrics
- invent sources
- make investment recommendations
- hide uncertainty
- replace validation

## Source Attribution

When real public documents are used, document:

- company name
- report name
- report period
- source file name
- source URL if applicable
- extraction method

## Portfolio Transparency

The README should clearly say whether the project uses:

- synthetic data
- manually extracted public data
- automatically extracted data
- real public reports

## Responsible Summary Generation

Executive summaries should use cautious language.

Allowed:

```text
The company shows higher debt-to-assets ratio than peers in this sample.
```

Not allowed:

```text
The company is unsafe or should be avoided as an investment.
```

## Final Rule

The project should demonstrate analytical responsibility. Trust is more important than automation.
